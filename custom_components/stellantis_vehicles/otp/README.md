# OTP module

This folder handles one-time passwords (OTP) for Stellantis vehicle accounts
(Peugeot, Citroën, DS). Some accounts need an OTP code, generated by the
InWebo service, in addition to the normal login. This code is the Python
version of the logic that InWebo's own mobile app uses internally, so this
integration can generate the same codes without needing a phone.

## What it does

1. **Activate a device**: the first time you set this up, the code
   registers a virtual "device" with InWebo, using an SMS code and a PIN
   you provide. This is a one-time step per account.
2. **Generate OTP codes**: once activated, the code can ask InWebo's server
   for a fresh OTP code whenever it's needed to log in.
3. **Save and reuse**: the result of activation (keys, device ID, etc.) is
   saved to a local file (`otp.bin`) so the device does not need to be
   re-activated every time.

## Files in this folder

- **`otp.py`** — the main client. Talks to InWebo's server over HTTPS,
  handles the activation flow, and computes OTP codes from the keys it
  receives.
- **`load.py`** — decodes the block of account/key data ("IW data") that
  InWebo sends back, and keeps it updated as the server sends changes.
- **`oaep.py`** — a small building block used to safely decrypt data sent by
  InWebo's server (a variant of RSA-OAEP encryption).
- **`tokenizer.py`** — a tiny helper that splits InWebo's data blob into
  individual fields.

## Notes

- This is a reimplementation of InWebo's official mobile SDK behavior in
  Python, based on how the real app communicates with the server.
- `otp.bin` stores the activated device's keys. If it becomes unreadable
  (for example, after an update that changes the internal format), it is
  simply discarded and the device is activated again.
